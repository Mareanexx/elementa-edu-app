# Главная, каталог, поиск и уведомления

Модуль `catalog-api` содержит чистые доменные модели и контракт `CatalogRepository`. В `catalog-impl` разделены Retrofit DTO, проверка и преобразование ответов, удалённый источник, локальная история, репозиторий и MVI каждого экрана. Android, Retrofit и Gson не входят в доменный модуль.

Реального сервера пока нет. В debug запросы проходят через авторизованный OkHttp и Retrofit с демонстрационным HTTP-перехватчиком. В release перехватчик отсутствует: требуется развернуть приведённые ниже ручки на сервере и указать `-Pelementa.authBaseUrl=https://<домен>/`. Значение по умолчанию `api.elementa.example` является заглушкой.

## Общие правила

- HTTPS, `Authorization: Bearer <access_token>`. Пользователь определяется по токену, идентификатор аккаунта в URL не передаётся.
- `Accept-Language: ru` для локализованного контента каталога. Тексты интерфейса клиента находятся в `catalog-impl/res/values/strings.xml`.
- Ответы JSON; даты ISO 8601 UTC. Отсутствующие необязательные даты, рейтинги, изображения и курсоры — `null`.
- Курсор непрозрачный, привязан к пользователю, фильтру, запросу и сортировке. Размер страницы `limit=20`, максимум 50. Порядок внутри снимка стабилен при изменении оценок; сервер должен обеспечивать это своим курсором.
- Ошибки: 401 — истекла сессия; 404 — объект удалён; 409 — курсор устарел; 422 — неправильный запрос; 429 — ограничение частоты; 5xx — сервис временно недоступен. Клиент различает отсутствие сети, тайм-аут и некорректный ответ.
- Ошибки фонового обновления оставляют ранее полученные карточки. Повтор после 409 начинает список заново.

## Ручки

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/users/me/home` | Агрегированная главная: продолжение чтения, быстрые счётчики, категории, книжные подборки, непрочитанные уведомления |
| GET | `/api/v1/catalog/categories` | Категории с описанием, ключом иллюстрации и количеством книг |
| GET | `/api/v1/catalog/books` | Каталог, фильтрация, поиск, сортировка, пагинация |
| GET | `/api/v1/catalog/search/suggestions` | Популярные поисковые запросы для начального состояния поиска |
| GET | `/api/v1/users/me/notifications` | Личная лента уведомлений |
| PUT | `/api/v1/users/me/notifications/{id}/read` | Идемпотентная отметка одного уведомления прочитанным |
| PUT | `/api/v1/users/me/notifications/read-state` | Прочтение уведомлений до границы полученного снимка |

### Главная

```json
{
  "continue_reading": [],
  "categories": [],
  "sections": [
    {"id": "popular", "sort": "popular", "books": []},
    {"id": "recommended", "sort": "recommended", "books": []},
    {"id": "newest", "sort": "newest", "books": []}
  ],
  "library_count": 12,
  "collection_count": 5,
  "unread": {"count": 3, "revision": 0}
}
```

`continue_reading` содержит только начатые, незавершённые книги; сервер располагает их по времени последнего чтения. Клиент показывает до пяти книг в карусели, со счётчиком, индикаторами и видимым краем следующей карточки. При отсутствии прогресса показывается приглашение выбрать книгу. `collection_count` считает пользовательские коллекции без системных «Избранное» и «Хочу прочитать»; `library_count` — объём личной библиотеки. Пустые подборки скрываются. Идентификаторы подборок текущего клиента: `popular`, `recommended`, `newest`.

### Книга в подборке, каталоге и поиске

```json
{
  "id": "book_1",
  "title": "Органическая химия",
  "authors": "А. И. Галочкин, И. В. Ананьина",
  "pages": 160,
  "pages_read": 48,
  "cover_url": null,
  "cover_key": "chemistry",
  "rating": {"average": 4.2, "count": 64},
  "tags": [{"id": "organic", "label": "Органическая химия", "kind": "topic"}],
  "favorite": false,
  "want_to_read": false,
  "collection_count": 0
}
```

Обязательные поля проверяются до попадания в UI: положительное число страниц, `0 <= pages_read <= pages`, рейтинг 1–5 с положительным количеством оценок, непустые ID и названия. При отсутствии обложки или ошибке загрузки отображается локальная иллюстрированная обложка. В поиске независимые бейджи показывают прогресс, избранное, «Хочу прочитать» и наличие пользовательских коллекций. После изменения подборок или чтения выдача обновляется без сброса строки поиска. Полные сведения открываются через существующий `BookRepository`. Кнопка продолжения передаёт `BookEntry.Reader`, не меняя прогресс. Действия меню используют существующие ручки избранного, списка чтения и коллекций из [контракта книги](book-api.md).

### Категории и выдача

Категория:

```json
{"id":"organic","title":"Органическая","description":"От строения молекул к механизмам реакций","icon_key":"organic","book_count":4}
```

Текущие ключи иллюстраций: `organic`, `inorganic`, `physical`, `analytical`, `biochemistry`, `general`. Названия и описания приходят с сервера. Одна книга может входить в несколько категорий; вкладка «Все» не дублирует книги.

Параметры `/catalog/books`:

- `category_id` — необязательная категория; без неё весь каталог.
- `query` — необязательная строка поиска. Нормализация Unicode NFKC, удаление внешних и повторяющихся пробелов. От 2 до 100 символов.
- `sort`: `recommended`, `popular`, `newest`, `title_asc`, `relevance`. Поиск использует `relevance`, каталог — выбранную сортировку.
- `cursor`, `limit` — пагинация.

Ответ: `{"items":[],"next_cursor":null,"total":0}`. `total` относится к текущему фильтру и запросу. Поиск сопоставляет начала слов в названии, авторе, темах и категориях, без учёта регистра и ё/е; выполняется на сервере, клиент не фильтрует загруженную страницу.

Ввод объединяется с задержкой 350 мс, IME запускает поиск сразу. Изменение строки отменяет старый запрос; дополнительный номер поколения защищает от запоздавшего ответа. Догрузка защищена от дублирования. Поиск с одной буквой не отправляется.

Подсказки: `{"queries":["Органическая химия","Космос"]}`. История из последних 8 запросов хранится локально, отдельно для каждого аккаунта, исключена из резервной копии. В неё попадают отправленные через IME запросы, выбранные подсказки и запросы, из которых открыли книгу; промежуточный ввод не сохраняется. Повторы сравниваются без учёта регистра и ё/е. Есть удаление отдельного запроса и очистка истории.

### Уведомления

Параметры: `filter=all|unread`, `cursor`, `limit`.

```json
{
  "items": [{
    "id": "notice_6",
    "sequence": 6,
    "title": "Новая подборка",
    "body": "Книги о химических реакциях и механизмах",
    "created_at": "2026-10-18T12:00:00Z",
    "read_at": null,
    "book_id": null,
    "category_id": "organic"
  }],
  "next_cursor": null,
  "snapshot_sequence": 6,
  "unread": {"count": 3, "revision": 0}
}
```

`sequence` монотонно растёт в пределах аккаунта. `book_id` или `category_id` задают переход; одновременно оба поля запрещены. Уведомление без перехода всё равно можно отметить прочитанным. Время показано относительно текущего момента, для старых событий — календарной датой.

Ответ обеих PUT-ручек: `{"read_at":"2026-10-18T12:05:00Z","unread":{"count":2,"revision":1}}`.

Тело `read-state`: `{"through_sequence":6}`. Новые события с `sequence > 6`, появившиеся после загрузки страницы, остаются непрочитанными. Повторный запрос безопасен; повтор после ошибки использует исходную границу снимка. `unread.revision` увеличивается при появлении события и изменении состояния прочтения. Клиент не заменяет счётчик ответом более старой ревизии.

Переход из уведомления выполняется сразу; отметка отправляется параллельно. Ошибка отметки сохраняет непрочитанное состояние и возможность повтора. Во время записи запоздавшая загрузка отменяется и не перезаписывает локальную отметку. После записи список перечитывается, в том числе в фильтре непрочитанных. Это внутриприкладная лента; доставка push-уведомлений потребует отдельной серверной интеграции.

## Демонстрационная среда

Debug-каталог использует общие книги, рейтинг, прогресс и принадлежность к коллекциям через `DemoBookLibraryBridge`. Прочтение уведомлений сохраняется отдельно для каждого аккаунта. Шесть стартовых уведомлений — пример серверного контента, а не реальные пользовательские события.

Для инструментальных проверок доступны debug-only настройки `catalog_mock_controls`: `delay_ms`, `next_status` (HTTP-код либо `-1` для ошибки сети), `page_size`, `empty_catalog`, `empty_notifications`. Проверки создают отдельные аккаунты и не сбрасывают данные пользователя.
