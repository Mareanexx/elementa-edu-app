# API экрана «О книге» Elementa

Модуль `book-api` содержит независимые от Android модели, валидацию и контракт репозитория. В `book-impl` отдельно находятся Retrofit API/DTO, преобразование ответов, источник данных, репозиторий, MVI и Compose UI. Клиент использует `elementa.authBaseUrl` (по умолчанию `https://api.elementa.example/`) и `Authorization: Bearer <access_token>`. Реальный сервер пока отсутствует: в debug те же HTTP-запросы обрабатывает сохраняющий данные демонстрационный сервер. Release не содержит моки.

## Методы

Все пути ниже начинаются с `/api/v1`. Идентификаторы книги, коллекции, отзыва и ответа непрозрачны для клиента. Сервер определяет аккаунт по токену и проверяет права при каждом обращении.

| Метод | Путь | Ответ и назначение |
|---|---|---|
| GET | `/books/{bookId}` | 200, `BookDetails` |
| PUT / DELETE | `/users/me/books/{bookId}/favorite` | 200, `Shelves`; добавить / убрать из избранного |
| PUT / DELETE | `/users/me/books/{bookId}/reading-list` | 200, `Shelves`; добавить / убрать из «Хочу прочитать» |
| GET | `/users/me/books/{bookId}/collections` | 200, `{ "items": [CollectionChoice] }`; пользовательские подборки и текущее включение книги |
| PUT | `/users/me/books/{bookId}/collections` | 200, `Shelves`; атомарно заменить включение книги в пользовательские подборки |
| GET | `/books/{bookId}/reviews` | 200, `ReviewsPage`; сортировка, оценка и курсор |
| PUT | `/books/{bookId}/reviews/me` | 200, `Review`; создать или изменить собственный отзыв |
| DELETE | `/books/{bookId}/reviews/me` | 204; удалить собственный отзыв и оценку |
| PUT | `/books/{bookId}/reviews/{reviewId}/reaction` | 200, `Review`; установить или снять реакцию |
| GET | `/books/{bookId}/reviews/{reviewId}/replies` | 200, `RepliesPage` |
| POST | `/books/{bookId}/reviews/{reviewId}/replies` | 201, `Reply`; отправить ответ с `Idempotency-Key` |
| DELETE | `/books/{bookId}/reviews/{reviewId}/replies/{replyId}` | 204; удалить собственный ответ |

PUT/DELETE членства в системных подборках идемпотентны. PUT пользовательских подборок принимает `{ "collection_ids": ["collection-uuid"] }`: отсутствующие в списке связи снимаются, пустой массив снимает все пользовательские связи. Системные подборки это действие не меняет. Все идентификаторы проверяются до записи; частичного изменения нет. Ответ всегда содержит актуальные признаки членства и число пользовательских подборок.

## Данные книги

```json
{
  "id": "book-uuid",
  "title": "Органическая химия",
  "authors": "А. И. Галочкин, И. В. Ананьина",
  "description": "Полный текст описания, включая абзацы…",
  "images": [
    { "id": "cover", "url": "https://cdn.example/cover.jpg", "caption": "Обложка" },
    { "id": "spread", "url": "https://cdn.example/spread.jpg", "caption": "Разворот книги" }
  ],
  "tags": [
    { "id": "advanced", "label": "Продвинутый", "kind": "difficulty" }
  ],
  "pages": 785,
  "pages_read": 48,
  "file_bytes": 5600000,
  "notes_count": 12,
  "rating": { "average": 4.5, "count": 10, "distribution": [0, 0, 1, 3, 6] },
  "shelves": { "favorite": true, "want_to_read": false, "collection_count": 2 },
  "metadata": {
    "publisher": "Издательство",
    "year": 2022,
    "language": "Русский",
    "isbn": "978-0-00000-000-0",
    "format": "EPUB"
  },
  "my_review": null,
  "preview_reviews": []
}
```

`pages` положительно, `pages_read` клиент ограничивает диапазоном 0…`pages`. Размер передаётся в байтах, UI показывает десятичные МБ. `notes_count` относится к текущему аккаунту. В этой задаче запись прогресса не выполняется: кнопка чтения открывает подготовленный маршрут будущего ридера с начальной страницей `pages_read + 1`, а для прочитанной книги — с первой.

`images` — упорядоченный список: первое изображение является обложкой. URL должны быть доступны текущему аккаунту; для реального сервера используются HTTPS/CDN. Пустой список даёт заглушку без открытия галереи. Клиент ограничивает список 50 изображениями и убирает дубликаты ID. Галерея поддерживает счётчик, листание, миниатюры, двойное нажатие и масштабирование двумя пальцами 1–5×. Состояния загрузки и ошибки изображения обрабатываются отдельно от книги.

`description` возвращается полностью. UI показывает до шести строк, полный текст открывается в прокручиваемом диалоге. Пустое описание отображается честной заглушкой. Поля издателя, года, языка и ISBN необязательны; отсутствующие строки скрываются. ISBN доступен для копирования.

Допустимые `kind` тегов: `topic`, `difficulty`, `format`, `year`; неизвестный вид отображается как тема. Пустые теги и дубликаты ID отбрасываются. `metadata`, `rating` и `shelves` обязательны. Отсутствующие обязательные поля или некорректный рейтинг дают ошибку ответа с возможностью повторить запрос.

В `rating.distribution` пять целых неотрицательных чисел: **от одной до пяти звёзд**. Их сумма равна `count`; при `count > 0` `average` — конечное число 1…5. Без оценок: `{ "average": null, "count": 0, "distribution": [0,0,0,0,0] }`. Рейтинг агрегируется по одной оценке каждого аккаунта, включая оценки без текста. `preview_reviews` содержит короткую подборку отзывов, `my_review` — единственный собственный отзыв либо null. Сохранение/удаление отзыва должно атомарно обновлять агрегат рейтинга; значения в библиотеке и коллекциях должны совпадать с деталями книги.

`CollectionChoice`:

```json
{ "id": "collection-uuid", "name": "Для практикума", "book_count": 3, "selected": true }
```

## Системные подборки

Аккаунт содержит «Избранное» (`kind: favorite`) и «Хочу прочитать» (`kind: reading_list`). Обе доступны через [API коллекций](collections-api.md), не входят в лимит 30 пользовательских подборок, не переименовываются и не удаляются. Сервер обязан гарантировать единственность каждой. Убирается только связь с книгой. Для существующих аккаунтов нужна миграция с созданием пустого списка чтения. После изменения членства клиент обновляет открытые коллекции в фоне, сохраняя прокрутку.

## Отзывы, реакции и обсуждения

```json
{
  "id": "review-uuid",
  "author_id": "user-uuid",
  "author_name": "Мария Белова",
  "avatar_url": null,
  "rating": 5,
  "text": "Понятные схемы и примеры",
  "created_at": "2026-10-18T09:30:00Z",
  "updated_at": null,
  "likes": 12,
  "dislikes": 1,
  "reaction": null,
  "reply_count": 2,
  "is_mine": false
}
```

Времена — ISO 8601 UTC. `is_mine` и `reaction` вычисляются сервером для текущего аккаунта. `avatar_url` необязателен: иначе показываются инициалы. PUT собственного отзыва принимает `{ "rating": 5, "text": "…" }`. Оценка обязательна, 1–5; текст необязателен, до 2000 символов UTF-16 после обрезки краевых пробелов. На аккаунт и книгу допускается один отзыв с оценкой: повторный PUT изменяет его и сохраняет ID и `created_at`, заполняя `updated_at`. DELETE идемпотентен; при удалении отзыва сервер также удаляет ответы и реакции на него.

Реакция принимает `{ "value": "like" }`, `{ "value": "dislike" }` или **явное** `{ "value": null }` для снятия. На аккаунт и отзыв допускается одна реакция; смена снимает предыдущую. На собственный отзыв реагировать нельзя (403). Повторное нажатие выбранной реакции снимает её. Счётчики обновляются только после успешного ответа.

GET отзывов принимает `sort`: `helpful`, `newest`, `rating_desc`, `rating_asc`; необязательные `rating=1..5`, `cursor`, `limit=10`. `helpful` сортирует по полезности (likes − dislikes), `newest` — по времени создания. Реальному серверу нужен стабильный порядок с ID как дополнительным ключом и непрозрачный курсор по ключам сортировки. Ответ:

```json
{ "items": [], "next_cursor": "opaque-or-null", "total_count": 64 }
```

`total_count` — число отзывов, удовлетворяющих фильтру. `next_cursor: null` завершает список. Клиент загружает следующую страницу по мере прокрутки и убирает дубли ID. При изменении фильтра/порядка старый запрос отменяется.

Ответ в обсуждении:

```json
{
  "id": "reply-uuid",
  "author_name": "Мария Белова",
  "avatar_url": null,
  "text": "Спасибо! С какой главы посоветуешь начать?",
  "created_at": "2026-10-18T09:35:00Z",
  "is_mine": true
}
```

GET ответов использует `cursor`, `limit=10`, тот же контейнер страницы и порядок от новых к старым. POST принимает `{ "text": "…" }`: непустой текст, не более 1000 символов UTF-16. Обязателен заголовок `Idempotency-Key: <UUID>`: сервер сохраняет ключ вместе с результатом, ограничивая его аккаунтом и обсуждением. Повтор с тем же ключом и текстом возвращает исходный ответ; другой текст с тем же ключом — 409. Это защищает от дубликатов при потере ответа после сохранения. Клиент сохраняет ключ и черновик после сетевой ошибки и меняет ключ при редактировании текста. Удаление чужого ответа — 403, повторное удаление собственного отсутствующего ответа — 204. Счётчик `reply_count` пересчитывается сервером.

## Ошибки и состояние клиента

Формат: `{ "error": { "code": "RATING_REQUIRED" } }`.

| HTTP | Код | Поведение |
|---|---|---|
| 401 | `UNAUTHORIZED` | Очистка сессии, возврат на гостевой экран |
| 403 | `OWN_REVIEW_REACTION`, `REPLY_FORBIDDEN` | Действие недоступно |
| 404 | `BOOK_NOT_FOUND`, `REVIEW_NOT_FOUND` | Книга или обсуждение недоступны |
| 404 | `COLLECTION_NOT_FOUND` | Предложение обновить подборки |
| 409 | `IDEMPOTENCY_CONFLICT` | Обновить данные и повторить |
| 422 | `RATING_REQUIRED`, `REVIEW_TOO_LONG`, `REPLY_REQUIRED`, `REPLY_TOO_LONG` | Ошибка рядом с формой |
| 429 | `RATE_LIMITED` | Сообщение о слишком частых запросах |
| 5xx | `UNAVAILABLE` | Сервис временно недоступен |

Сетевое отключение, тайм-аут и некорректный ответ различаются. Первый запрос показывает скелетон; повторное обновление сохраняет содержимое и показывает небольшой индикатор синхронизации. Изменения не отображаются успешными до подтверждения сервера. Повторные нажатия блокируются; формы сохраняют данные после ошибки. Автоматический повтор изменяющих запросов отключён. Отмена корутин не преобразуется в сетевую ошибку.

## Демонстрационный сервер и проверки

Debug-моки используют общий с коллекциями каталог и связи. Отзывы и ответы хранятся в `book_demo_server`, агрегаты для карточек — в `book_rating_mock_cache`. Авторство и реакции привязаны к аккаунту, сами отзывы общие для книги. `book_1` содержит обложку и два явно обозначенных демонстрационных изображения; `book_2` — одну обложку; `book_12` — пример без обложки и оценок. Тесты создают отдельные аккаунты и очищают только собственные данные.

SharedPreferences `book_mock_controls`: `next_status` — одноразовый HTTP-статус, `-1` — потеря соединения; `delay_ms` — задержка 0…5000 мс; `drop_reply_after_save=true` — один раз сохранить ответ, затем оборвать соединение. Повтор с прежним ключом не создаёт ещё один ответ.

Проверки покрывают HTTP-контракт, преобразование и ошибки, конкурирующие запросы MVI, идемпотентность ответа, связь с коллекциями и UI-сценарии на PROD Pixel 9a. Переключение на реальный сервер требует настройки базового URL, отключения `elementa.mockAuth` и реализации этого контракта на сервере.
