# API «Моей библиотеки» Elementa

`user-library-api` — JVM-модуль с доменными моделями, правилами поиска и контрактом репозитория. `user-library-impl` содержит отдельно Retrofit/DTO, преобразование, источник данных, историю поиска, репозиторий, MVI и Compose UI. UI не формирует HTTP-запросы и не хранит серверные состояния самостоятельно.

Запросы используют общий базовый адрес `elementa.authBaseUrl` и `Authorization: Bearer <access_token>`. По умолчанию адрес — `https://api.elementa.example/`. В debug запросы обрабатывает сохраняющий состояние HTTP-мок. Реальный сервер нужно реализовать по этому контракту; release не содержит демонстрационный транспорт.

## Методы

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/users/me/library` | Постраничная библиотека, категории, поиск и счётчики |
| GET | `/api/v1/users/me/library/preferences` | Сохранённая сортировка |
| PATCH | `/api/v1/users/me/library/preferences` | Изменение сортировки |
| PUT | `/api/v1/users/me/library/books/{bookId}/reading-status` | Ручная отметка прочитанной или сброс прогресса |

Агрегированный GET `/library` отдаёт книги вместе со счётчиками и обзорными секциями. Он не меняет существующий контракт `/library/books`, который используется выбором книг в коллекциях.

Сервер определяет аккаунт по токену, проверяет принадлежность книги библиотеке и права на каждое действие. Библиотека содержит доступные аккаунту книги; добавление новых книг относится к будущему каталогу.

Избранное, «Хочу прочитать» и пользовательские подборки используют существующий [API книги](book-api.md). Выбор подборок из меню открывается поверх библиотеки, сохраняя её положение и выбранную вкладку. Повторных независимых списков для библиотеки нет. Открытие карточки ведёт в «О книге», стрелка — непосредственно в подготовленный маршрут ридера. Назад из такого маршрута возвращает в библиотеку. Пока ридер не подключён, открытие маршрута не записывает прогресс.

## Выдача

Параметры GET:

- `status`: `all`, `in_progress`, `completed`, `want_to_read`.
- `query`: необязательный поисковый запрос, 2–100 символов UTF-16 после нормализации пробелов. Пустая строка означает обычную библиотеку.
- `sort`: `recent`, `title_asc`, `author_asc`.
- `cursor`: непрозрачный серверный курсор следующей страницы.
- `limit`: клиент передаёт 20; сервер ограничивает размер страницы.

```json
{
  "items": [
    {
      "id": "book-uuid",
      "title": "Органическая химия",
      "authors": "А. И. Галочкин, И. В. Ананьина",
      "pages": 160,
      "pages_read": 48,
      "reading_status": "in_progress",
      "cover_url": "https://cdn.example/organic.jpg",
      "cover_key": "chemistry",
      "rating": { "average": 4.2, "count": 64 },
      "tags": [
        { "id": "organic", "label": "Органическая химия", "kind": "topic" }
      ],
      "favorite": true,
      "want_to_read": false,
      "collection_count": 1
    }
  ],
  "next_cursor": "opaque-or-null",
  "total_count": 12,
  "counts": { "all": 12, "in_progress": 2, "completed": 1, "want_to_read": 0 },
  "highlights": {
    "in_progress": [],
    "completed": [],
    "want_to_read": []
  }
}
```

`total_count` учитывает поиск и выбранную вкладку. `counts` учитывает поисковый запрос **до фильтра вкладки**, поэтому позволяет перейти к другим категориям того же поиска. При пустом запросе это счётчики всей библиотеки. В процессе и прочитанные — непересекающиеся статусы; список «Хочу прочитать» может пересекаться с ними.

`highlights` возвращается на первой странице `all` без поискового запроса: до двух начатых, восьми прочитанных и восьми запланированных книг. Обзорные секции формируются сервером независимо от постраничного списка. Остальные книги показываются сеткой в две колонки; уже показанные в обзорных секциях ID исключаются из сетки. На вкладке прочитанных — крупная горизонтальная карусель с догрузкой, в процессе — карточки с прогрессом, запланированные — сетка. Поисковая выдача во всех вкладках использует компактный вертикальный список.

`pages` положительно, `pages_read` находится в 0…`pages`. Статусы: `not_started` — 0 страниц, `in_progress` — начатая книга, `completed` — все страницы. `collection_count` считает только пользовательские подборки, максимум 30. Пустая/недоступная обложка заменяется оформлением по `cover_key`. Рейтинг необязателен; некорректный необязательный рейтинг скрывается. Теги содержат стабильный ID, подпись и вид `topic`, `difficulty`, `format`, `year`. Пустые теги и дубликаты ID отбрасываются.

Для `recent` реальный сервер использует последнее взаимодействие с книгой/время добавления, для алфавитной сортировки — русскую локаль. Во всех порядках нужен стабильный дополнительный ключ ID. Курсор должен учитывать владельца, запрос, статус, сортировку и ключи последнего элемента; при смене условий старый курсор неприменим. Ответ с `next_cursor: null` завершает список. Дубли ID между страницами клиент убирает.

## Поиск

Поиск выполняется на сервере по названию, авторам и темам. Клиент ждёт 350 мс после изменения ввода, а кнопка поиска на клавиатуре отправляет запрос сразу. Одна буква не отправляется. При новом запросе прежняя загрузка отменяется, её результат не может заменить актуальную выдачу. Повторное нажатие клавиши поиска не дублирует уже выполняющийся запрос.

Для реального сервера нужны индексы по поисковым полям и нормализация регистра, пробелов и вариантов «е/ё». В демонстрационном сервере слова запроса ищутся совместно в объединённом тексте названия, автора и тегов, без учёта регистра. Для больших библиотек эту демонстрационную реализацию нельзя заменять выгрузкой всего каталога на клиент.

Последние восемь запросов сохраняются **локально и отдельно для каждого аккаунта** только при подтверждении поиска или открытии результата. Историю можно очистить. Она не отправляется отдельным запросом на сервер и исключена из резервного копирования.

## Сортировка и статус

Настройки:

```json
{ "sort_order": "title_asc" }
```

GET/PATCH возвращают этот объект. Порядок меняется в UI после успешного PATCH и применяется ко всем вкладкам и поиску. При ошибке остаётся прежний порядок и открытый диалог с сообщением.

Изменение статуса:

```json
{ "status": "completed" }
```

PUT принимает `completed` или `not_started` и возвращает обновлённый объект книги. Первое устанавливает `pages_read = pages`, второе — 0. Клиент запрашивает подтверждение обоих действий. Сохранённые оценки, отзывы, избранное и подборки не меняются. Перед записью сервер проверяет права и выполняет изменение атомарно. Повтор одинаковой команды не создаёт дополнительных сущностей. Запись фактической позиции чтения будет отдельной частью ридера; произвольный пользовательский статус `in_progress` этой ручкой не устанавливается.

После успешной записи обновляются кэш вкладок, счётчики и открытые коллекции. Книга и коллекции читают тот же прогресс. Кэш сохраняет карточки при фоновом обновлении, включая уже загруженные пустые состояния; повторного скелетона при каждом входе нет. Скелетон со скруглением 16 dp нужен при первой загрузке. Синхронизация показывается компактным индикатором над нижней навигацией.

## Ошибки

Формат: `{ "error": { "code": "CURSOR_EXPIRED" } }`.

| HTTP | Код | Поведение |
|---|---|---|
| 401 | `UNAUTHORIZED` | Сессия очищается, открывается гостевой экран |
| 404 | `BOOK_NOT_FOUND` | Книга недоступна; предложить обновление |
| 409 | `CURSOR_EXPIRED` | Повтор начинает выдачу с первой страницы |
| 422 | `INVALID_QUERY`, `INVALID_PREFERENCES`, `INVALID_READING_STATUS` | Некорректный запрос |
| 429 | `RATE_LIMITED` | Сообщение о слишком частых запросах |
| 5xx | `UNAVAILABLE` | Временная недоступность |

Отключение сети, тайм-аут и некорректный ответ различаются. При первой ошибке показана карточка с повтором. Ошибка следующей страницы не удаляет уже загруженные книги. Ошибка фонового обновления сохраняет содержимое и показывает snackbar с действием «Обновить». Ошибка ручной смены статуса остаётся в диалоге, прежний прогресс сохраняется. Отмена корутины не считается сетевой ошибкой; автоматический повтор изменяющих запросов отключён.

## Проверки HTTP-моков

Библиотека использует общий с коллекциями демонстрационный каталог из 12 книг. Личные системные подборки и прогресс привязаны к аккаунту. Прогресс хранится в `collections_demo_server` под отдельными ключами `progress_<userId>_<bookId>`; старые значения без записи продолжают использовать исходные демонстрационные данные. Сортировка и время изменений — `library_demo_server`, история — `library_search_history`. Данные демо-аккаунта не сбрасываются.

SharedPreferences `library_mock_controls`: `next_status` — одноразовый HTTP-статус (`-1` — потеря соединения), `delay_ms` — задержка 0…5000 мс, `empty_library=true` — пустая выдача, `page_size` — уменьшенный размер страницы для проверки пагинации. `search_requests` и `last_query` позволяют проверить число отправленных поисковых запросов. Это инструменты debug-проверки, отсутствующие в release.

Модульные тесты проверяют debounce, отмену старого поиска, повторный ввод, кэш, ошибки, сортировку, смену статуса и курсоры. Инструментальные сценарии на PROD Pixel 9a проверяют интерфейс, свайпы, карусель, поиск, историю, переходы, общие подборки и прогресс. Используются отдельные QA-аккаунты с очисткой только их данных.
