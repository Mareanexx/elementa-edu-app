# Профиль, достижения и настройки

В debug запросы проходят через Retrofit и локальный перехватчик OkHttp. Демо-сервер
сохраняет профиль, аватар и настройки отдельно для каждого пользователя. В release
перехватчика нет: используется `elementa.authBaseUrl`, как и для авторизации.

## Авторизация

Все запросы требуют `Authorization: Bearer <access_token>`. Сетевой слой получает
действующий токен через `AccessTokenProvider`, не обращаясь к формату зашифрованной
сессии. HTTP 401 завершает локальную сессию и возвращает пользователя на вход.
Сервер обязан определять пользователя по токену, проверять владение данными и
валидировать запросы независимо от клиентских проверок.

## Ручки

| Метод и путь | Назначение | Успешный ответ |
| --- | --- | --- |
| `GET /api/v1/users/me` | Профиль со статистикой | `200`, полный профиль |
| `PATCH /api/v1/users/me` | Изменение имени, логина и описания | `200`, полный профиль |
| `PUT /api/v1/users/me/avatar` | Загрузка фото | `200`, полный профиль с новым `avatar_url` |
| `DELETE /api/v1/users/me/avatar` | Удаление фото | `200`, полный профиль с `avatar_url: null` |
| `GET /api/v1/users/me/achievements` | Все достижения с прогрессом | `200`, объект с `items` |
| `GET /api/v1/users/me/settings` | Настройки пользователя | `200`, настройки |
| `PATCH /api/v1/users/me/settings` | Сохранение настроек | `200`, подтверждённые настройки |

Запросы не повторяются автоматически. Во время изменения соответствующие действия
заблокированы; при ошибке введённые данные остаются в форме для исправления и повтора.

## Профиль

```json
{
  "id": "user-1",
  "full_name": "Мария Химик",
  "username": "maria_chem",
  "description": "Изучаю химию по книгам",
  "avatar_url": "https://cdn.example.org/avatars/user-1.jpg",
  "statistics": {
    "books_read": 24,
    "notes_published": 41,
    "tests_passed": 8
  }
}
```

`avatar_url` может быть `null`. Остальные поля обязательны, показатели статистики
неотрицательны. Фото и статистика не входят в запрос редактирования:

```json
{
  "full_name": "Мария Химик",
  "username": "maria_chem",
  "description": "Изучаю химию по книгам"
}
```

Имя: 2–80 символов после удаления пробелов по краям, хотя бы одна буква.
Логин: 3–32 символа по `[a-zA-Z][a-zA-Z0-9_]{2,31}`, регистронезависимый,
нормализуется в нижний регистр. Описание: до 250 символов, может быть пустым
или содержать переносы строк. Поле ограничивает ввод и вставку 250 символами; счётчик
показывает длину текста и лимит. Сервер должен атомарно менять профиль и данные
аккаунта: следующий вход должен работать с новым логином. В демо это реализовано.

Перед уходом из изменённой формы приложение предлагает сохранить редактирование
или отказаться от него. При отсутствии изменений запрос не нужен.

## Фото

`PUT` принимает `multipart/form-data`, часть `file` с именем файла и `Content-Type`
`image/jpeg` или `image/png`, размер до 5 МиБ. Сервер должен проверять фактическое
изображение, повторно декодировать его и не доверять имени файла или MIME-заголовку.
Рекомендуется возвращать новый URL после каждой замены, чтобы кеш не показывал
старое фото. `DELETE` не удаляет сам профиль.

Клиент открывает системный Photo Picker либо внешнее приложение камеры. Широкий
доступ к галерее и собственное разрешение камеры не запрашиваются. Снимок камеры
передаётся через FileProvider с доступом только к временному файлу.

Исходное фото до 20 МиБ копируется во временный каталог приложения. Декодирование
ограничено 2048 пикселями по длинной стороне, учитывает EXIF-ориентацию. В редакторе
доступны перемещение, масштаб 100–300% и поворот на 90°. Результат — квадратный
JPEG 512×512, без исходных EXIF-метаданных; в профиле он отображается круглым.
Отмена выбора, съёмки или редактирования сохраняет прежний аватар.

Системные контракты: [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker),
[FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider).

## Достижения

```json
{
  "items": [
    {
      "id": "reader_50",
      "title": "Библиотека знаний",
      "description": "Прочитай 50 книг и собери фундамент знаний.",
      "category": "reading",
      "art": "pink",
      "current": 24,
      "target": 50,
      "unit": "книг",
      "unlocked_at": null
    }
  ]
}
```

Категории: `reading`, `notes`, `tests`, `habits`. Оформление `art`: `red`, `blue`,
`orange`, `pink`; неизвестный вариант использует синий значок. Идентификаторы
уникальны, `current >= 0`, `target > 0`. `unlocked_at` — `null` либо дата получения
в формате `YYYY-MM-DD`. Полученное достижение требует `current >= target`.
Решение о выдаче принимает сервер, клиент показывает его результат.

При открытии профиля видна нижняя панель с несколькими достижениями. Во время
свайпа вверх она следует за пальцем; после отпускания или нажатия «Показать все»
плавно расширяется до полного экрана. Скругления уменьшаются, нижнее меню
сворачивается. Стрелка «Назад» и системный возврат запускают обратную трансформацию.
Категории оформлены как вкладки библиотеки и переключаются горизонтальным слайдом,
в том числе свайпом. Карточки занимают две равные колонки и имеют одинаковую высоту.

Полученные и ещё не полученные достижения разделены на группы. Неполученные значки
приглушены; диалог показывает условие, прогресс и количество до цели, а для
полученных — дату. Загрузка профиля и достижений отображается скелетоном со
скруглениями 16 dp, как у остальных скелетонов приложения.

## Настройки

```json
{
  "text_scale": 1.1,
  "reduce_motion": false,
  "keep_screen_on": false,
  "haptic_feedback": true
}
```

Все поля обязательны. Масштаб текста — 0.9–1.3, интерфейс предлагает шаг 0.1.
Системный масштаб шрифта также учитывается. Уменьшение анимации отключает слайды
внутри профиля, раскрытие панели, анимацию выбранной вкладки и мерцание скелетона.
Удержание экрана включённым действует,
пока открыт авторизованный интерфейс Elementa. Тактильный отклик применяется к
выбору вкладок и подтверждению смены фото.

Настройки применяются после успешного ответа сервера, сохраняются локально
по id пользователя и переживают перезапуск. При ошибке остаются прежние значения.
Очистка кеша изображений выполняется на устройстве и не требует ручки бека:
очищается только кеш Coil, профиль и исходный аватар не удаляются. Выход использует
существующий сценарий завершения локальной сессии, описанный в `auth-api.md`.

## Ошибки

Формат совместим со схемой авторизации:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "field_errors": {
      "username": "USERNAME_TAKEN"
    }
  }
}
```

Поддерживаются `full_name`, `username`, `description`; коды полей:
`INVALID_NAME`, `INVALID_USERNAME`, `USERNAME_TAKEN`, `DESCRIPTION_TOO_LONG`,
`REQUIRED`. Неизвестные поля игнорируются, диагностический текст сервера
пользователю не показывается.

| Статус | Поведение |
| --- | --- |
| 400, 422 | Ошибка формы с подписями у полей |
| 401 | Возврат на приветственный экран после завершения сессии |
| 409 | Логин занят, подпись под полем логина |
| 408, 504 | Тайм-аут, можно повторить |
| 413 | Фото превышает допустимый размер |
| 415 | Неподдерживаемое изображение |
| 429 | Просьба подождать перед повтором |
| 500–599 | Временная недоступность сервиса |

Отдельно обрабатываются отсутствие подключения, повреждённый ответ сервера,
неверные значения в успешном ответе и сбой локального сохранения.

## Структура кода

- `user-profile-api`: чистый Kotlin/JVM — модели, контракт репозитория,
  валидация и сценарии изменения профиля и аватара.
- `user-profile-impl/data`: Retrofit API, DTO, преобразователи, сетевой и локальные
  источники, реализация репозитория. Демо-сервер существует только в `src/debug`.
- `user-profile-impl/presentation`: отдельные MVI-состояния, события и ViewModel
  профиля, достижений и настроек; экраны и компоненты с текстом из ресурсов модуля.
- `app`: сборка зависимостей, авторизованные HTTP-запросы, нижнее меню и применение
  настроек ко всему авторизованному интерфейсу.

## Проверка

Войти можно под `chemist` / `Elementa123`. У демонстрационного пользователя есть
статистика, полученные и неполученные достижения. У новых аккаунтов статистика
начинается с нуля. `taken_user` при редактировании логина имитирует конфликт 409.
Профиль и настройки сохраняются после перезапуска; изменение логина доступно для
последующего входа с прежним паролем.

UI-тесты создают собственные аккаунты и удаляют только свои фикстуры. Для проверки
внешней камеры и галереи они подменяют результат системного приложения тестовым
изображением, проходя реальные контракты Activity Result, редактор и multipart-загрузку.
Дополнительно проверяются цвета системных отступов, одинаковые размеры карточек,
промежуточные положения панели при раскрытии и возврате, свайпы вкладок и отсутствие
индикаторов загрузки вместо скелетона.
