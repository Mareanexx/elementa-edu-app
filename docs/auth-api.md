# Авторизация Elementa

Клиент поддерживает регистрацию и вход по имени пользователя. В debug-сборке
запросы Retrofit обрабатывает локальный перехватчик OkHttp. Доступ к сети для
демо не нужен. В release-сборке перехватчик отсутствует; потребуется настоящий
HTTPS-сервер с описанным ниже контрактом.

## Запросы

Все тела запросов и ответов имеют формат JSON. Имена пользователей регистронезависимы:
клиент обрезает пробелы по краям и переводит латинские буквы в нижний регистр.
Пароль передаётся без изменения пробелов и регистра.

`POST /api/v1/auth/register`

```json
{
  "full_name": "Мария Химик",
  "username": "maria_chem",
  "password": "Elementa123"
}
```

`full_name`: 2–80 символов после обрезки пробелов, хотя бы одна буква.
`username`: 3–32 символа, регулярное выражение `[a-zA-Z][a-zA-Z0-9_]{2,31}`.
`password`: 8–128 символов, хотя бы одна буква и одна цифра.
Повтор пароля проверяется на клиенте и в запрос не входит. Сервер должен
самостоятельно проверять все ограничения и уникальность имени пользователя.

`POST /api/v1/auth/login`

```json
{
  "username": "chemist",
  "password": "Elementa123"
}
```

При входе клиент проверяет только заполненность полей, чтобы новые правила
регистрации не блокировали существующие аккаунты.

## Успешный ответ

Регистрация возвращает `201 Created`, вход — `200 OK`. Оба запроса создают сессию:

```json
{
  "access_token": "opaque-access-token",
  "refresh_token": "opaque-refresh-token",
  "token_type": "Bearer",
  "expires_in": 3600,
  "user": {
    "id": "a4fbc01c-25ec-47b4-8e14-60ece92a3df2",
    "username": "maria_chem",
    "full_name": "Мария Химик"
  }
}
```

Все поля обязательны. `expires_in` — положительное целое число секунд, не больше
31536000. Клиент устанавливает время окончания сессии относительно времени
получения ответа. Сессия сохраняется до перехода на «Главную».

Токены и пользовательские данные шифруются AES-GCM; ключ хранится в Android
Keystore. Файл сессии исключён из облачного резервного копирования и переноса
на другое устройство. Пароли форм не сохраняются в DataStore, SavedStateHandle
или журнале и очищаются после успешного запроса.

Обновление токенов пока не реализовано: по истечении `expires_in` нужен повторный
вход. Refresh token сохраняется для последующего подключения обновления.
Выход сейчас локальный. Для серверного отзыва сессии и удаления аккаунта
понадобятся отдельные ручки. После подтверждённого удаления или отзыва вызывайте
`AuthRepository.clearSession()`; приложение вернётся на приветственный экран.

## Ошибки

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "field_errors": {
      "username": "USERNAME_TAKEN",
      "password": "WEAK_PASSWORD"
    }
  }
}
```

`field_errors` и `retry_after_seconds` необязательны. Поддерживаемые ключи полей:
`full_name`, `username`, `password`. Неизвестные ключи игнорируются, неизвестные
коды поля показывают общее сообщение о некорректных данных. Текст серверных
диагностических сообщений пользователю не выводится.

| HTTP | Код сервера | Поведение клиента |
| --- | --- | --- |
| 400, 422 | `VALIDATION_ERROR` | Сообщение формы и подписи к указанным полям |
| 401 | `INVALID_CREDENTIALS` | Общее сообщение о неверном логине или пароле |
| 403 | `ACCOUNT_DISABLED` | Сообщение об ограничении доступа |
| 409 | `USERNAME_TAKEN` | Ошибка под полем имени пользователя |
| 408, 504 | `REQUEST_TIMEOUT` | Предложение повторить запрос |
| 429 | `RATE_LIMITED` | Отсчёт до повторной попытки, кнопка временно выключена |
| 500–599, кроме 504 | `SERVICE_UNAVAILABLE` | Сообщение о временной недоступности |

Для `429` серверу следует возвращать заголовок `Retry-After` с целым количеством
секунд или `error.retry_after_seconds`. Клиент ограничивает ожидание диапазоном
1–300 секунд; без значения ждёт 30 секунд. HTTP-дата в `Retry-After` пока не
поддерживается. Классификация общей ошибки опирается на HTTP-статус.

Отдельно обрабатываются отсутствие подключения, тайм-аут транспорта, неполный
или некорректный успешный ответ и ошибка сохранения сессии на устройстве.
Автоматический повтор POST отключён: повтор регистрации после тайм-аута может
вернуть занятое имя, если первый запрос уже создал аккаунт. В таком случае
пользователь может перейти на вход с теми же данными.

## Состояния и навигация

`AuthIntent → AuthViewModel → AuthUiState → Compose`.
ViewModel управляет формой, валидацией, запросом и отсчётом ограничения частоты.
Экран передаёт события и отображает неизменяемое состояние. Отдельный чистый
`AuthReducer` пересчитывает ошибки при редактировании связанных полей.
Доменная валидация отделена от API DTO и репозитория.

`SessionViewModel` наблюдает сохранённую сессию. Пока она загружается, виден
индикатор. Без сессии открывается Welcome с переходами на вход и регистрацию.
С сессией открывается пустая «Главная» с кнопкой выхода. После успешного запроса
граф авторизации убирается из композиции, поэтому «Назад» не возвращает к форме.

Переход вперёд выполняется слайдом справа налево за 360 мс; возврат назад и
выход из аккаунта идут в обратную сторону. Экран под передним планом смещается
на треть ширины. Загрузка сохранённой сессии не запускает слайд.
Общий боковой отступ контента — 16 dp. Иллюстрация на Welcome прижата к правому
краю, кнопки имеют высоту 60 dp и промежуток 8 dp.
Фон Welcome, входа и регистрации белый; заливка полей — `#E7E7F1`.
Вопрос об аккаунте и ссылка на другую форму расположены в одной строке;
нажать можно на выделенное действие. Строка находится внизу формы с отступом
24 dp над безопасной областью. При открытой клавиатуре содержимое прокручивается.

Во время запроса поля, переключение формы и навигация назад заблокированы.
Повторные нажатия не отправляют второй запрос. Ошибки полей появляются после
потери фокуса или отправки формы; редактирование повторно проверяет затронутое
поле. Системная клавиатура поддерживает «Далее», «Готово» и скрытый ввод пароля.
Формы прокручиваются при открытой клавиатуре. Социальный вход и восстановление
пароля не отображаются, поскольку соответствующих серверных сценариев пока нет.

## Разделение слоёв

`features/auth/auth-api` — чистый Kotlin/JVM-модуль: доменные модели, контракт
`AuthRepository`, `AuthValidator` и сценарии `LoginUseCase` / `RegisterUseCase`.
Он не зависит от Android, Retrofit и хранилищ. Сценарии проверяют данные и
нормализуют логин до вызова репозитория, оставляя пароль без изменений.

`features/auth/auth-impl/data` содержит отдельные файлы для DTO, Retrofit API,
источников данных и преобразователей ответов. `DefaultAuthRepository` согласует
получение и сохранение сессии; `RetrofitAuthRemoteDataSource` отвечает за HTTP,
а `AuthSessionLocalDataSource` — за сериализацию сохранённой сессии.
Внешняя сборка зависимостей доступна через `AuthRepositoryFactory`.

`core/datastore` хранит зашифрованную строку, не зная о DTO и доменных моделях.
`SecureSessionStore` отвечает за DataStore, `AndroidKeystoreSessionCipher` —
за шифрование. Формат сохранённой сессии и ключ шифрования сохраняют совместимость
с предыдущей версией приложения.

`features/auth/auth-impl/presentation` разделён на маршруты, экраны, компоненты
формы и MVI. Состояние, события, редьюсер и ViewModel лежат в отдельных файлах.
`AuthViewModel` зависит от доменных сценариев и создаётся через
`AuthViewModelFactory`; маршруты связывают жизненный цикл с отображением.

Зависимости собирает `AppContainer` уровня Application. Корневая навигация,
состояние сессии и пустая «Главная» находятся в отдельных пакетах `app`.
Демо-перехватчик и хранилище демо-аккаунтов разделены и входят только в debug.

## Проверка на моках

Соберите `:app:assembleDebug` и установите APK на `PROD_-_Pixel_9a`.
Обычный аккаунт для входа: `chemist` / `Elementa123`.
Для регистрации используйте новый логин и пароль по правилам выше. После
выхода новый аккаунт доступен для входа даже после перезапуска приложения.
Демо хранит в SharedPreferences соль и PBKDF2-хеш пароля; файл исключён из
резервного копирования. Это тестовая имитация сервера, а не механизм
локальной авторизации для release.

Для ошибок введите один из специальных логинов и любой непустой пароль:

| Логин | Результат |
| --- | --- |
| `offline_user` | Ошибка подключения |
| `timeout_user` | Тайм-аут |
| `server_error` | HTTP 503 |
| `blocked_user` | HTTP 403 |
| `invalid_response` | Некорректный ответ HTTP 200 |
| `validation_error` | HTTP 422 с ошибкой поля логина |
| `rate_limit` | Первая попытка в процессе получает HTTP 429 и отсчёт 10 секунд |
| `taken_user` | При регистрации HTTP 409 |

Любой незарегистрированный логин или неверный пароль дают HTTP 401. Задержка
мока — 1,2 секунды, чтобы можно было увидеть загрузку. Для `rate_limit` после
отсчёта действует обычная проверка учётных данных. Мок не учитывает системный
авиарежим: сетевую ошибку проверяйте через `offline_user`.

Проверьте пустую форму, ограничения полей, несовпадение паролей, показ пароля,
переключение экранов, загрузку, повтор после ошибки, успешную регистрацию,
выход, вход зарегистрированным пользователем и восстановление «Главной» после
перезапуска. После проверки можно выйти, чтобы снова увидеть Welcome.

## Подключение сервера

Для release задайте Gradle-свойство `elementa.authBaseUrl` с HTTPS-адресом,
заканчивающимся `/`, например `-Pelementa.authBaseUrl=https://api.example.org/`.
Адрес по умолчанию `https://api.elementa.example/` — заглушка, действующего
сервера пока нет. В debug моки включены, в release выключены.

Документация архитектурного подхода: [UI layer Android](https://developer.android.com/topic/architecture/ui-layer).
