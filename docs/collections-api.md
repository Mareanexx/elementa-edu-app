# API коллекций Elementa

Клиент использует Retrofit и общий авторизованный OkHttp-клиент. Адрес задаёт `elementa.authBaseUrl`; по умолчанию это адрес-заглушка `https://api.elementa.example/`. Все запросы содержат `Authorization: Bearer <access_token>`. Сервер обязан определять владельца по токену и проверять доступ к коллекции и книге при каждом действии.

В debug HTTP-запросы перехватывает демонстрационный сервер. Данные сохраняются отдельно для каждого аккаунта в `collections_demo_server`; release не содержит этой реализации. Реальный сервер пока нужно реализовать по этому контракту.

## Методы

| Метод | Путь | Ответ | Действие |
|---|---|---|---|
| GET | `/api/v1/users/me/collections` | 200, `{ "items": [Collection] }` | Все коллекции аккаунта |
| POST | `/api/v1/users/me/collections` | 201, `Collection` | Создание |
| POST | `/api/v1/users/me/collection-covers` | 201, `CollectionImage` | Загрузка фотографии обложки |
| PATCH | `/api/v1/users/me/collections/{id}` | 200, `Collection` | Название и обложка |
| DELETE | `/api/v1/users/me/collections/{id}` | 204 | Удаление подборки, книги остаются в библиотеке |
| GET | `/api/v1/users/me/collections/{id}/books` | 200, `{ "items": [Book] }` | Книги подборки |
| POST | `/api/v1/users/me/collections/{id}/books` | 204 | Добавление книг без дубликатов |
| DELETE | `/api/v1/users/me/collections/{id}/books/{bookId}` | 204 | Удаление связи с книгой |
| GET | `/api/v1/users/me/library/books` | 200, `{ "items": [Book] }` | Доступные для добавления книги библиотеки |
| GET | `/api/v1/users/me/collection-preferences` | 200, `Preferences` | Настройки аккаунта |
| PATCH | `/api/v1/users/me/collection-preferences` | 200, `Preferences` | Сохранение настроек |

## Объекты

`Collection`:

```json
{
  "id": "collection-uuid",
  "name": "Органическая химия",
  "cover_key": "chemistry",
  "cover_image": { "id": "image-uuid", "url": "https://cdn.example/cover.jpg" },
  "book_count": 3,
  "kind": "custom"
}
```

Для создания и обновления передаются `name`, `cover_key` и `cover_image_id`. Название после удаления пробелов по краям и объединения повторяющихся пробелов содержит 1–60 символов UTF-16. Имена уникальны для пользователя без учёта регистра. Допустимые обложки: `chemistry`, `molecules`, `reactions`, `laboratory`, `notes`, `space`. Неизвестная обложка из ответа отображается как `chemistry`.

`cover_image` необязателен; `null` означает стандартную обложку. Выбор стандартного оформления отправляет явное `"cover_image_id": null`, снимая прежнюю фотографию. Сохранение с фотографией передаёт идентификатор загруженного изображения. Сервер проверяет принадлежность изображения текущему пользователю. При ошибке загрузки картинки клиент показывает стандартное оформление.

Загрузка фотографии — `multipart/form-data` с единственной частью `image`, типом `image/jpeg` и именем файла `collection-cover.jpg`. Ответ `CollectionImage`: `{ "id": "image-uuid", "url": "https://cdn.example/cover.jpg" }`. Клиент читает исходник объёмом не более 20 МиБ, учитывает ориентацию EXIF, обрезает по центру до 1280×800 и отправляет JPEG без исходных метаданных, не более 2 МиБ. Сервер самостоятельно проверяет формат, объём и размеры изображения. Для реального сервера нужно удаление временных загрузок по TTL, если пользователь отменил создание или редактирование и изображение осталось без ссылки. Демонстрационный сервер хранит файлы приватно, отдельно для каждого аккаунта; автоматической очистки таких загрузок в нём пока нет.

В аккаунте всегда одна системная коллекция с `kind: "favorite"`. Она закреплена первой, не входит в лимит **30 пользовательских коллекций**, не переименовывается и не удаляется. В неё можно добавлять и из неё можно убирать книги. Лимит и уникальность имени сервер проверяет атомарно при сохранении.

`Book`:

```json
{
  "id": "book-uuid",
  "title": "Органическая химия",
  "authors": "Авторы учебника",
  "description": "Описание книги",
  "pages": 240,
  "pages_read": 48,
  "cover_key": "chemistry",
  "cover_url": null,
  "rating": { "average": 4.7, "count": 128 },
  "tags": [
    { "id": "advanced", "label": "Продвинутый", "kind": "difficulty" },
    { "id": "space", "label": "Космос", "kind": "topic" }
  ]
}
```

`rating` и `tags` возвращают те же GET-методы книг коллекции и библиотеки. `rating: null` означает отсутствие оценок; иначе `average` — конечное число от 0 до 5, `count` — положительное количество оценок. Некорректный необязательный рейтинг не отображается. Тег содержит стабильный `id`, серверный `label` и `kind`: `topic`, `difficulty`, `format` или `year`. Неизвестный вид отображается как обычная тема; пустые теги и повторяющиеся идентификаторы отбрасываются. Отсутствующие теги дают пустой список. Рейтинг и теги пока доступны для чтения; выставление оценок не входит в этот экран.

`cover_url` необязателен. При отсутствии или ошибке загрузки показано оформление `cover_key`. Добавление принимает `{ "book_ids": ["book-uuid"] }`. Повторное добавление не создаёт дубликаты. Операция выполняется целиком: недоступная книга даёт ошибку, частичного изменения нет. Удаление связи идемпотентно. Удаление коллекции не затрагивает книги и другие подборки.

`pages_read` возвращается GET-методами книг коллекции и библиотеки. При отсутствии принимается 0; клиент ограничивает значение диапазоном от 0 до `pages`. У начатой книги отображаются прогресс и число прочитанных страниц. Запись прогресса относится к будущей интеграции ридера.

Свайп влево сразу убирает книгу из списка и отправляет DELETE связи. При ошибке карточка возвращается на прежнее место. Действие «Отменить» повторно добавляет связь POST-запросом; сам файл книги и запись в библиотеке сохраняются. Переход на отдельный экран книги будет подключён позднее; временного диалога информации нет.

`Preferences`:

```json
{
  "sort_order": "name_asc",
  "show_empty": true
}
```

Порядки: `name_asc`, `name_desc`, `books_desc`, `books_asc`. Клиент загружает настройки перед списком и сохраняет изменения PATCH-запросом; локальное хранилище — кэш последнего успешного ответа. Сортировка до 31 карточки выполняется на клиенте с русским алфавитом; при равном количестве книг используется название. Фильтр пустых подборок применяется к пользовательским коллекциям, «Избранное» видно всегда. Настройки общие для обзора и полного списка.

## Ошибки

Формат: `{ "error": { "code": "NAME_TAKEN" } }`.

| HTTP | Код | Смысл |
|---|---|---|
| 401 | `UNAUTHORIZED` | Сессия завершилась, приложение возвращает к авторизации |
| 403 | `COLLECTION_PROTECTED` | Изменение системной коллекции запрещено |
| 404 | `COLLECTION_NOT_FOUND` | Подборка отсутствует или недоступна |
| 409 | `NAME_TAKEN` | Имя занято |
| 409 | `COLLECTION_LIMIT_REACHED` | Достигнут лимит 30 |
| 422 | `NAME_REQUIRED`, `NAME_TOO_LONG` | Ошибка поля названия |
| 422 | `INVALID_BOOKS` | Недоступные идентификаторы книг |
| 422 | `INVALID_COVER`, `INVALID_PREFERENCES` | Неверные значения перечислений |
| 422 / 413 | `INVALID_COVER_IMAGE` | Некорректная или слишком большая фотография |
| 429 | `RATE_LIMITED` | Слишком много запросов |
| 5xx | `UNAVAILABLE` | Временный сбой |

Ошибки поля остаются под полем; сетевые ошибки — в текущем диалоге или на экране с повтором. Введённое название и выбранная обложка сохраняются после ошибки. Повторная отправка и закрытие формы блокируются на время изменения. Автоматический повтор изменяющих запросов отключён. Для поддержки нескольких устройств серверу также потребуются транзакции и уникальные ограничения на владельца/имя и коллекцию/книгу.

## Проверка моков

Демо-аккаунт `chemist / Elementa123` содержит шесть тематических подборок и книги в избранном. Новый аккаунт начинает с пустого избранного. Каталог содержит 12 демонстрационных книг. Тесты используют отдельные временные аккаунты.

Одноразовая инъекция ошибок: SharedPreferences `collections_mock_controls`, `next_status`: HTTP-статус, `-1` для ошибки соединения. Значение потребляется следующим запросом коллекций, библиотеки или настроек.
